# 写作手册

> 给不需要懂代码的人看的。照着抄就行。
>
> 这份手册放在 `_dev/` 里，**不在网站上**。文中提到的路径（`assets/img/` 等）
> 都是相对**项目根目录**说的，不是相对这个文件。

---

## 一句话版本

写一章内容，你只需要会三件事：

1. **标题** —— 在行首打 `#`，`##`，`###`（数字越大标题越小）
2. **卡片** —— 写 `> [!tip] 标题`，不用再碰 `<div>`
3. **图片** —— 直接拖进来

其余的（表格、点数、链接）下面都有模板，复制粘贴改字即可。

---

## 一、五种卡片

旧写法要写 `<div class="tip-card"><div class="tip-title">…</div><p>…</p></div>`，现在一行搞定：

### 提示卡（蓝色）

```markdown
> [!tip] 你已经了解这个世界了吗？
>
> 本章节将引导新玩家了解宝可梦世界的设定。
> 若你已熟悉这些内容，可直接跳转。
```

### 规则卡（黄色，自带 ⚠️）

```markdown
> [!rule] 行动掷骰公式为：
>
> **能力值/社交属性 + 技能**，自由组合构建骰池。
```

### 叙事者笔记（紫色，给 GM 看）

```markdown
> [!gm]
>
> 你可以通过一个或多个现有的地区来构建你的故事。
```

不写标题就会自动显示「🎭 叙事者笔记」。

### 训练家贴士（绿色）

```markdown
> [!trainer]
>
> 宝可梦中心内**禁止**对战。
```

不写标题自动显示「💡 训练家贴士」。

### 译注（可折叠）

```markdown
> [!note] 译注
>
> 「ステータス」官中是“能力”，本规则书译作「能力值」以作区别。
```

折叠面板，点开才展开。不写标题就默认「译注」。

### 三个要点

- `[!tip]` 方括号里**不能有空格**，`[! tip]` 不生效。
- 标题和正文之间建议加一行 `>`，不加也能识别（会按换行切开）。
- 正文的每一行都要以 `>` 开头，包括空行（空行就写一个 `>`）。

### 中文也行

`[!提示]` `[!规则]` `[!叙事]` `[!训练家]` `[!译注]` 与英文写法等价，记不住英文就写中文。

## 二、标题

```markdown
# 章节名          ← 一级，一篇只能有一个
## 大节           ← 二级，会出现在侧边栏
### 小节          ← 三级，展开后出现在侧边栏
#### 更小的       ← 四级，不进侧边栏
```

**编辑器快捷键**：Typora 用 `Ctrl+1/2/3`，Obsidian 同样。

⚠️ `##` 和文字之间**必须有空格**。`##技能` 不生效，`##　技能`（全角空格）虽然能显示但会让锚点错乱，别用。

## 三、属性点数

| 写法 | 显示效果 |
|---|---|
| `{{3}}` | ●●● |
| `{{2/5}}` | ●●○○○ |
| `{{1/3/5}}` | ●○○○○（●=已有，●=可加，○=空） |

写在正文或表格里都行，例如：

```markdown
你的力量是 {{3/5}}，属于良好水平。
```

## 四、表格

表格是唯一还需要记符号的地方，但编辑器都能一键生成，不用手打。

### 手写模板

```markdown
| 点数 | 效果 |
|------|------|
| {{1/5}} | 一阵强风就能把你吹倒。 |
| {{2/5}} | 你的力气普普通通，平时能够拧开泡菜罐子。 |
| {{3/5}} | 朋友搬家时总会喊你去帮忙搬家具。 |
```

第二行 `|------|------|` 是分隔线，**必须有**，列数要和表头一致。

### 不想手打？

- **Typora**：菜单「段落 → 表格」，或 `Ctrl+T`，弹出网格点几下就生成
- **Obsidian**：装 `Advanced Tables` 插件后，`Tab` 键自动对齐、自动补分隔线

## 五、图片

### 放哪里

所有图片统一放 **`assets/img/`** 目录，文件名用**英文或拼音**（中文和空格会让链接变成一长串 `%E5%8F%AF...`，容易出错）。

```
assets/img/trainer-licence.webp   ✅
assets/img/联盟徽章.webp           ⚠️ 能用但不建议
assets/img/my photo.webp          ❌ 空格会断链
```

**格式用 `.webp`**。同一张角色卡截图，PNG 要 2 MB，WebP 只要 50 KB，肉眼几乎看不出差别——
手机读者等的是这 40 倍的差距。截图工具存出来是 PNG 的话，用 [squoosh.app](https://squoosh.app) 拖进去转一下即可。

### 怎么写

```markdown
![宝可梦联盟徽章](assets/img/league-badge.webp)
```

方括号里是**图片说明**（图挂了会显示这段字，读屏软件也读它），圆括号里是**路径**。
单独占一行的图片会自动加一圈浅边框和圆角，不用额外写 HTML。

### 怎么让它自动完成

**Typora**：`文件 → 偏好设置 → 图像`，选「复制到指定路径」，填 `./assets/img`。
之后截图直接 `Ctrl+V` 粘贴，图片自动存进目录、自动生成链接。

**Obsidian**：`设置 → 文件与链接`，把「附件默认位置」设为「指定的文件夹」并填 `assets/img`，「使用 Wiki 链接」**关闭**。
之后同样直接粘贴。

> 这一条是「图片不好插」的根本解药——不是语法问题，是编辑器有没有配好粘贴路径。

## 六、选哪个编辑器

| | Typora | Obsidian | VS Code |
|---|---|---|---|
| 价格 | 约 ¥89 买断 | 个人免费 | 免费 |
| 所见即所得 | ✅ 最彻底 | ✅ 源码/预览可切换 | ❌ 只有预览 |
| 表格编辑 | ✅ 可视化网格 | 需装插件 | ❌ |
| 粘贴图片 | ✅ 自动落盘 | ✅ 自动落盘 | 需插件 |
| 卡片显示 | 普通引用块 | ✅ 装 CSS 片段后是彩色卡片 | ❌ |
| 适合 | **纯写作** | **写作 + 资料管理** | 改代码 |

**建议**：只写规则书 → **Typora**；还想管设定集、图鉴、剧情线 → **Obsidian**。

用 Obsidian 的话，把 `assets/obsidian-callouts.css` 复制到 `<你的库>/.obsidian/snippets/`，再到「设置 → 外观 → CSS 代码片段」启用，`[!gm]` 这类自定义卡片就会显示成和网站一样的颜色。

## 七、旧写法对照表

改稿时遇到旧内容，按这个换：

| 旧写法 | 新写法 |
|---|---|
| `<div class="tip-card"><div class="tip-title">T</div><p>C</p></div>` | `> [!tip] T` + `>` + `> C` |
| `<div class="rule-card"><div class="rule-title">T</div><p>C</p></div>` | `> [!rule] T` + `>` + `> C` |
| `<div class="storyteller-note"><div class="note-label">🎭 叙事者笔记</div><p>C</p></div>` | `> [!gm]` + `>` + `> C` |
| `<div class="trainer-tip"><div class="tip-label">💡 训练家贴士</div><p>C</p></div>` | `> [!trainer]` + `>` + `> C` |
| `<details class="translator-note">…</details>` | `> [!note] 译注` + `>` + `> C` |
| `<div class="collapsible-insert">` + `onclick="toggleInsert(this)"` | `<details class="collapsible-insert">` + `<summary class="insert-header">`（见第八节） |

`01-marvelous-world.md` 和 `02-system-explained.md` 里原有的 16 处卡片已经自动转换完毕，旧文件备份在 `_backup-2026-10-26/`。

## 八、折叠块

### 普通折叠块（推荐，纯语法）

```markdown
> [!details] 📋 点我展开
>
> 这里是被折叠的内容。
> 可以放列表、表格、卡片。
```

不需要写任何 HTML，键盘 `Tab` 也能选中、回车展开。

### 带徽章的折叠块（需要 HTML）

「📋 宝可梦联盟 训练家规则集」那种带头部徽章的样式，目前还得用 HTML，但已经不需要任何脚本：

```html
<details class="collapsible-insert">
    <summary class="insert-header">
        <span class="insert-badge">📜 徽章文字</span>
        <span class="insert-title">标题文字</span>
        <span class="arrow">
            <svg viewBox="0 0 24 24"><path d="M6 9l6 6 6-6"/></svg>
        </span>
    </summary>
    <div class="insert-body">
        内容
    </div>
</details>
```

**要点**：
- 用 `<details>` + `<summary>`，浏览器原生负责开合，不依赖 JS
- `summary` 必须是 `details` 的**直接子元素**，放在第一个
- 里面的四个小节用 `<div class="sub-section"><div class="sub-section-title">小节名</div>…</div>` 包起来

这种块全站目前只有一个。以后要用就**整块复制再改字**，别从零写。

> 旧写法 `<div class="collapsible-insert">` + `onclick="toggleInsert(this)"` 已经不再需要，而且在新版里点了没反应——如果你从旧备份里粘贴了内容，请换成上面的写法。

## 九、写新章节的流程

1. 复制 `02-system-explained.md` 当模板，改名成 `03-character-creation.md`
2. 把里面的内容全删掉，只留第一行 `# 章节名`
3. 打开 `_sidebar.md`，在对应位置加一行（**一章一条**）：
   ```markdown
   - **[👤 角色创建](03-character-creation.md)**
   ```
   注意是 `- **[标题](文件.md)**`：粗体里包链接，渲染出来是一整行可点的章节入口。
   **不要**在这里写 `###` 之类的小节——页内的小节会自动出现在右侧「本页目录」里。
4. 开始写。写到 `##` / `###` / `####` 都会自动进右侧目录，不用手工维护
5. 本地预览：双击项目根目录的 **`启动预览.bat`**，浏览器会自动打开
   （不用再敲 `npx serve .` 了，那个要联网装包；现在这个是本地自带、离线可用的）

### 加了新章节，搜索和离线要另外配置吗？

不用。三件事都是自动的：

- **搜索**：索引是从 `_sidebar.md` 的链接现抓的，缓存 1 小时。新章节上线后，最多一小时（或刷新一次浏览器缓存）就能搜到。
- **离线**：`.md` 走「网络优先」，新章节联网读过一次就会存进浏览器，之后断网也能看。旧缓存不会挡住新内容。
- **`.webp` 插图**：同理，第一次加载就会缓存，第二次打开走本地。

唯一需要手动维护的是 `sw.js` 里的 `PRE_MD` 列表——它决定「第一次访问就预先下载哪些章节」，让读者不用逐章点开也能离线读全书。新章节不加进去也能正常读（联网看过就缓存），加进去只是让首次离线更完整。

## 十、常见错误

| 现象 | 原因 |
|---|---|
| 卡片没变成卡片，还是一段引用 | 方括号里多了空格（`[! tip]`），或 `>` 后面漏了空格 |
| 标题没生效 | `#` 和文字之间漏了空格 |
| 侧边栏锚点跳不到 | 标题里有全角空格或特殊符号 |
| 右侧「本页目录」没出现 | 这一页的 `##` 少于 3 个；目录只在宽屏（≥1280px）显示 |
| 图片显示不出来 | 路径写错，或文件名带空格/中文；检查是不是放在 `assets/img/` |
| 表格错乱 | 第二行分隔线的列数和表头不一致 |
| 点数显示成 `{{3}}` 原文 | 花括号用了全角 `｛｝` |
| 折叠块点了没反应 | 用的是旧写法 `onclick="toggleInsert(this)"`，换成 `<details>`（见第八节） |
| 正文里的 `#/系统详解` 点了 404 | docsify 是按**文件名**找 `.md` 的，中文页名不是文件名。要写 `<a href="#/02-system-explained">`，锚点则写 `#/02-system-explained?id=等级` |

## 十一、发布上线

改完内容 → 双击根目录的 **`一键发布.bat`** → 按提示回车 → 完成。

它会做三件事：列出你改过哪些文件、问你一句「这次改了什么」、然后提交并推送到 GitHub。
推送成功后，GitHub Pages 大约 **30 秒**自动重新构建，刷新线上页面就是新的。

- 提交说明随便写，一句话就行。直接回车会生成「更新内容 2026-10-27 18:06」这种。
- 断网也不怕：本地提交会保留，联网后再点一次这个文件就行。
- 它只做「暂存 + 提交 + 推送」，**不会删除文件、不会强推、不会回滚**。
