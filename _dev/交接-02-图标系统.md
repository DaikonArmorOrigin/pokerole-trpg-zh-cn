# 交接 02 · 图标系统

> 这一份讲**图标从哪来、怎么嵌、什么时候用组件什么时候用位图**。
> 完整的图标清单（文件名 / 中文名 / 英文名 / 原书页码 / 含义）在 `图标调用表.md`，这里不重复。

---

## 一、一句话原则

> **图标里有文字或数字 → 做组件；纯图形 → 做位图。**

这条是踩了四五次坑才总结出来的。凡是带可变内容（数字、勾叉、箭头）的徽章，
做成位图就等于把内容写死，后面一定返工。

## 二、四种嵌入方式

### 1. 短标签 `<poke-icon>`（固定图形，推荐）

```html
<poke-icon class="mv powder"></poke-icon>
<poke-icon class="cat physical"></poke-icon>
<poke-icon class="ball dusk"></poke-icon>
<poke-icon class="mv reaction lg"></poke-icon>   <!-- lg = 图例大号 -->
```

类名规则：文件 `mv-powder.webp` → `class="mv powder"`。
映射表在 `theme.css` 里由脚本按文件名生成，**加图标要同步加一行**。

### 2. `<img class="mv-icon">`（需要 alt 时）

```html
<img class="mv-icon" src="assets/img/mv-powder.webp" alt="粉末类招式" width="20" height="20">
```

背景图拿不到 alt，纯装饰用 `<poke-icon>` 就够了；承载关键信息时用这个。

### 3. `<icon-frame>`（参数化徽章）

```html
<icon-frame class="flinch"><b>畏缩</b><span>3</span></icon-frame>
<icon-frame class="reaction"><b>反应</b><span>↑1</span></icon-frame>
<icon-frame class="power"><b>威力</b><span>3</span></icon-frame>              <!-- 招式卡上的威力 -->
<icon-frame class="power boost physical"><b>威力</b><span>+3</span></icon-frame>  <!-- 道具威力提升 -->
<icon-frame class="burn"><b>灼伤1</b><span class="always"></span></icon-frame>    <!-- 勾 -->
<icon-frame class="heal"><b>回复</b><span>X</span></icon-frame>                    <!-- X 是占位符 -->
```

- `<b>` 是顶部标题（**写中文**），`<span>` 是白框里的内容
- `class` 决定底色：状态异常 `burn` / `burn2` / `burn3` / `frozen` / `paralysis` /
  `confuse` / `love` / `poison` / `poison2` / `sleep`；增减益 `buff` / `debuff` /
  `damage` / `accuracy` / `heal` / `target` / `self` / `priority`
- 内容槽可以是文字、数字、`X`、`↑1`、`<span class="always">`（绿勾）、`<span class="never">`（红叉）
- **内部全部用 em**，改 `font-size` 就能整体缩放（速查页表格里就是 `font-size: .8rem`）

### 4. `<span class="field-chip">`（纯文字标签）

```html
<span class="field-chip">不可闪避</span>
```

原书里 `No Evasion` / `No Items` / `Change Type` 这几个没有内容槽，就是一整块深色圆角块。

### 5. `<span class="clock">`（持续时间表盘）

```html
<span class="clock scene"></span>          <!-- 完整场景 -->
<span class="clock" data-n="3"></span>     <!-- 持续 3 轮 -->
```

底图是原书 p.437 的表盘，数字用 `::after { content: attr(data-n) }` 叠上去。

### 核心技术：把整页背景图换成透明

图标都是矢量，但画在整页纸纹位图上。做法：

```python
page.replace_image(背景图xref, stream=1×1透明PNG)
pix = page.get_pixmap(clip=..., alpha=True)
```

纸色直接消失，图标自带透明底，边缘保持矢量原样。比泛洪去底省事得多。

### 道具册（p.116–129）要额外加一步

同样的替换背景只解决纸纹，**解决不了表里的矢量色块**：p0 的粉色「新手必备」框、
p10 的表头条、每张表的浅灰行底，都是矢量矩形，会一起进画面。所以渲染完还要
「从四边泛洪吃底色」，且候选色要取**边框上所有占比够大的颜色**（行底 219 灰、
行缝 240 灰是两层，只吃一种会留一整块灰底）。每吃一种都量一次剩余不透明比例，
低于 10% 就当误吃图标、退回上一版。

## 四、踩过的坑（按血泪程度排）

### 1. 带数字的图标别做位图
POWER、Reaction、Duration 三处都返工过。做之前先问一句「这里面的内容会不会变」。

### 2. 看到图标里有字母，先按「占位符」假设
`Damage X`、`Heal X` 的 X 是**填数字的地方**，不是符号本身。
我曾经把 Heal 的 X 脑补成「不回 HP」，写进说明栏，是错的。

### 3. 精灵球别用圆蒙版
圆蒙版是给「捕捉」册用的（球在彩色表格里）。道具册的球画在浅灰行底上，圆蒙版会：
- 把旧式球顶上的旋钮切掉
- 圆心对不准，球变歪椭圆

正解：透明底渲染 + 四边泛洪 + alpha 包围盒裁切。

### 4. 尺寸要按「固定裁切框」统一，不是按外接框
各球按外接框各自缩放，会让**大师球**（两侧有凸起）、**旧式球**（顶上有旋钮）的球体变小。
改成所有球都用同一个 32×32pt 的框套住圆心，输出再统一缩放。

### 5. `strip_bars` 会误删球体
判「整行 80% 同色 → 残留色条」时，球的**白色下腹**也满足条件，会把球压扁。
要加白名单：只有「有彩色或偏暗」的行才算色条。

### 6. 泛洪要跑两遍
第一遍可能只吃到上一行的粉色表头，第二遍才吃行底色。

### 7. 裁切框边缘会带进碎片
表格竖线、相邻字母都会被带进来。用「只保留最大连通块」过滤。

### 8. 源文件本身可能是坏的
道具册 p.122 那枚黑暗球右边缘是条**直线**，球被裁掉一块——不是抠图问题。
只能以圆心为轴镜像左半边补回来。

### 9. 横向图标在正方盒子里会被压扁
分类图标是 46×27（1.7:1）。`poke-icon` 默认 1.25em 正方，要单独给
`poke-icon.cat { width: 2.08em }`；`lg` 版本再算一次 `width: 4.42em`。

### 10. 道具名靠字体认，别靠坐标
道具册里道具名用 **BlissfulThinking**，章节小标题用 **TrebuchetMS-Bold**。
按字号筛会把「Revive 章节标题」和「Revive 道具」混成一条 —— 先到先得，最后
`item-revive.webp` 抠到的是粉色标题条。按字体筛一次就分开了。

### 11. 名字左边不一定有图标
`Leaf Stone` 在原书里被拆成 `Leaf` + `Stone` 两个 span，图标贴在 `Leaf` 左边。
所以只认「每行第一个 ≥14pt 的 span」，第二个 span 一律跳过，否则会多出一个
`item-stone.webp`（内容是隔壁的字母）。

### 12. em 与 rem 的坑
`.clock` 的宽高是 `1.95em`，em 跟**继承的字号**走。直接改 width/height 只会让框变大、
里面数字不变。要放大就改 `font-size`。

## 五之二、道具图标（`item-*`）

和招式图标那套是平行的一套：`item-<英文名 slug>.webp`，透明底、96×96 画布、
内容统一缩到 84px，所以防狼喷雾（6×20pt）和露营炉具（28×21pt）放进同一个方框
也不会一大一小。

```html
<img class="item-icon" width="18" height="18" src="assets/img/item-antidote.webp" alt="解毒药">
```

`.item-icon` 比 `.ball-icon` 大一号（1.5em vs 1.25em）：原书里道具图标约是字高的
1.6 倍，精灵球只有 1.13 倍 —— 这不是手滑，照着原书量的。

`itemprice.md` 里 84 个道具行全部带上图标，由 `_dev/apply_item_icons.py` 批量写入，
**别手改那一列**：重跑脚本会按英文名重新对一遍，手改过的格式会被覆盖。
持有物那两张表（属性强化 18 件 + 其它 42 件）原书就没有图标，脚本会跳过。

## 五之三、画布规格（2026-10-29 定稿）

图标分两类，**归一化方式不一样，别混用**：

| 类别 | 文件 | 规则 | 脚本 |
|---|---|---|---|
| 精灵球 | `ball-*` | 128×128 画布，**球身直径 104px**（占 81%），装饰可以伸出画布 | `_dev/normalize_balls.py` |
| 章节标记 | `ch-*` | 128×128 画布，**整图长边 112px**（占 87.5%） | `_dev/normalize_icons.py` |

### 为什么要按「球身」而不是整图

第一版是按整图外接框归一化的，结果旧式精灵球（顶上带旋钮）、究极球（两侧有翼）
的球身被挤小了一圈——整图一样大，球身却小 10%，摆在一列里一眼就能看出来。

现在的做法：用**腐蚀法**求出图标里最大的实心圆（就是球身）——反复腐蚀 alpha 掩膜，
腐蚀到只剩一点时，腐蚀次数就是半径——然后把球身直径统一到 104px、球心对齐画布中心。
翼、旋钮这类装饰不参与尺寸计算，该伸出去就伸出去。代码在 `normalize_balls.py`。

实测 29 个球全部落在 102~104px（`timer` 差 2px 是装饰干扰，肉眼无感）。

## 五之五、精灵球的图从哪来

> 2026-10-29 补了 8 枚**洗翠（《传说 阿尔宙斯》）**的球：飞羽 / 飞翼 / 飞梭、
> 沉重球·洗翠 / 超重 / 巨重、起源、奇异。这批只有 **LA 版** sprite（100×100），
> 没有 ZA 版，文件名叫 `Bag_<中文名>_LA_Sprite.png`。
> 注意洗翠沉重球是 `Bag_沉重球_LA_Sprite.png`，别拿成 `_ZA_`（那是现代的按体重款）。

**除了 `ball-old` 和 `ball-dynamax`，全部来自 52poke 的 ZA 版背包图标。**
（`ball-old` 是动画原创、`ball-dynamax` 是剑盾特殊球，52poke 没有 sprite，
保留原书 PDF 抠的那版。）

```bash
python _dev/fetch_balls_52poke.py    # 抓 27 张原图到 _dev/tmp/balls/
python _dev/normalize_balls.py       # 按球身归一化，输出到 assets/img/
```

抓图走 MediaWiki 的 API（`action=query&prop=imageinfo`），
**不要猜 `thumb/<hash>/<hash>/` 的哈希**——那是文件内容的 MD5，猜不出来。
API 直接返回原图地址（`media.52poke.com/wiki/...`），原图 160×160 RGBA。
直接请求 `s1.52poke.com` 的缩略图会被 403，要带 `Referer: https://wiki.52poke.com/`。

### 走过的一段弯路（别重复）

第一版这 13 个球是**手绘**的（PIL 画圆 + 画纹样），理由是想"保持和原书一致"。
结果和原作差得远：纹样是几何图形拼的、没有渐变和阴影，一眼能看出是山寨货。
已删掉 `_dev/draw_balls.py`。

**结论：有官方 sprite 就别自己画。** 52poke 那套 ZA 图标是同一批渲染，
27 个球风格完全一致，比手绘强得多。

### 球名和说明也以 52poke 为准

- **译名**：`沉重球`（不是重量球）、`贵重球`（不是珍惜球）、`究极球`（不是 UB 球）。
  05 章和 itemprice 要一致，改一处就得两处都改。
- **官方「包包说明」**：由 `_dev/fetch_ball_desc.py` 抓取，取**该球首次出现世代**那一条
  （`{{包包信息框|世代|版本|...}}` 里的第一条，wiki 本身按世代排好了序）。
  显示在球名下面一行小字（`.ball-note`），规则书自己的机制描述保留在「效果」列。

  两个例外，都写在脚本注释里了：
  - **精灵球**：第 1 世代那条是空的（`&mdash;`）、第 2 世代只有一句"捕捉宝可梦的道具。"，
    改用第 3 世代那句"用于投向野生宝可梦并将其捕捉的球。它是胶囊样式的。"
  - **公园球**：第 2 世代是捕虫大赛版（和竞赛球重复），本作用的是伙伴公园，

  `旧式精灵球` 和 `极巨球` 52poke 没有，不显示说明。

## 六、面向读者的速查页

`icons.md`，侧栏「🔍 图标速查」。内容由脚本从数据字典生成，**不要手改**
（几十行表格手写太容易错）。要改就重新生成。

**精灵球那一节已经删掉了**（2026-10-29）：球的价格、封印强度、效果在
`itemprice.md` 里讲得更全，速查页再列一遍是重复。别再往这里加回来。

表格里的尺寸规则在 `theme.css`：

```css
.markdown-section table poke-icon     { width: 2.8em; }
.markdown-section table poke-icon.cat { width: 4.8em; }
.markdown-section table icon-frame    { font-size: 0.8rem; }
.markdown-section table .clock        { font-size: 1.35rem; }
```

三种东西视觉高度都是 42px。**加新组件进表格时，记得也给它一条尺寸规则**，
不然会像 `.clock` 那次一样漏掉。
